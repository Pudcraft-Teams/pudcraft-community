# 移动端 UI 补齐设计文档

> **日期**：2026-04-01
> **状态**：已确认，待书面复核
> **分支**：`codex/mobile-ui-pass`

---

## 1. 背景

Pudcraft Community 当前已经具备论坛、服务器、服主控制台、管理后台等核心页面，但移动端体验仍然偏向“桌面布局压缩版”，存在以下共性问题：

- 全局导航与移动端菜单功能齐全但信息分组松散，搜索入口过窄，发帖 FAB 与页面操作存在并列但不统一的情况。
- 论坛广场、圈子页、帖子详情和圈子设置等页面，桌面侧栏与操作区在移动端没有完整重排，导致关键动作不够靠前。
- 服主控制台与管理后台虽然提供了移动端入口，但导航、切换、当前态表达和滚动行为仍不够稳定。

本次工作目标不是重做全站视觉体系，而是在现有 Warm Clay Community UI 语义和组件体系上，补齐移动端应有的导航、筛选、操作和布局能力。

## 2. 目标与非目标

### 2.1 目标

- 统一移动端全局导航、搜索、发帖入口和菜单信息结构。
- 让论坛核心页面在小屏下首屏即可完成主要动作：浏览、加入圈子、发帖、筛选、进入管理。
- 让服主控制台、管理后台和圈子设置页在移动端具备稳定可用的导航和操作入口。
- 保持桌面端信息架构不变，避免本次改动演变为全站重设计。
- 为并行开发提供清晰边界，减少共享组件冲突。

### 2.2 非目标

- 不引入新的全局路由体系，例如新增底部 Tab Bar 或改写站点导航架构。
- 不修改数据模型、API 协议或业务权限规则。
- 不对桌面端进行大规模视觉翻新，只做必要的兼容性调整。
- 不新增重量级依赖，不引入新的状态管理方案。

## 3. 设计原则

### 3.1 移动端优先，但不破坏桌面结构

优先保证 `sm` 以下到 `md` 之间的布局与操作路径清晰。桌面端仅接受随共享组件自然带出的轻量调整。

### 3.2 共享交互优先于页面局部补丁

凡是多个页面都会用到的移动端行为，优先抽到共享组件或共享样式模式中处理，例如：

- 顶部菜单中的信息分组
- 小屏搜索入口
- 横向滚动 tabs / chips
- 页头动作区
- FAB 与页面内主操作按钮的协同关系

### 3.3 首屏露出关键动作

移动端首屏优先展示“用户下一步最可能做的事”，而不是桌面侧栏信息的简单降级搬运。

### 3.4 风格延续

继续使用现有 Warm Clay Community UI 色板、圆角、边框和 `m3-*` 旧 token，不改动整体视觉语言。

## 4. 范围拆分

本次设计按三个并行实施域拆分。

### 4.1 共享移动端骨架

覆盖全局导航、移动端菜单、顶部搜索、全局发帖 FAB 以及多个页面共用的移动端操作布局。

### 4.2 论坛移动端

覆盖：

- 广场首页 `/`
- 圈子页 `/c/:slug`
- 探索页 `/explore`
- 帖子详情 `/post/:postId` 与 `/c/:slug/post/:postId`
- 圈子设置 `/c/:slug/settings`

### 4.3 控制台与后台移动端

覆盖：

- 服主控制台 `/console` 及其子页
- 管理后台 `/admin` 及其子页
- 与后台导航模式一致的移动端设置页导航

## 5. 共享移动端骨架设计

### 5.1 全局 Header

保留现有顶部 sticky header，但移动端行为改为“搜索优先、菜单清晰、动作集中”。

要求：

- 保留左侧品牌入口和右侧移动菜单入口。
- 移动端搜索不再只显示过窄输入框，而是提供足够点击面积的搜索触发区，展开后可直接输入并跳转。
- 菜单内容按“主导航”“个人操作”“管理入口”分组，避免现有平铺式长列表。
- 已登录态在菜单中同时保留用户信息、通知入口、个人主页、控制台、收藏、退出等能力。
- `admin` 角色入口单独高亮，但仍放在个人区语义内，不与主站导航混排。

### 5.2 全局发帖 FAB

全局 FAB 保留，因为它已经符合论坛主操作预期，但需解决两类问题：

- 在存在页面内主操作按钮时，避免 FAB 与页面主按钮形成竞争。
- 在移动端长页面中，FAB 与底部内容、评论输入区、分页控件之间应保持安全间距。

设计决定：

- FAB 继续固定右下角。
- 统一按钮尺寸、阴影、偏移和安全边距。
- 页面内若已有主操作按钮，FAB 不移除，但其文本语境由页面头部动作补足，不再要求 FAB 单独承担全部语义。

### 5.3 通用移动端操作条模式

为论坛页头、后台导航和设置页 tab 统一一套小屏操作条模式：

- 容器支持横向滚动。
- 当前态在颜色、背景和阴影上明确区分。
- 按钮最小触控高度不少于现有 `m3-chip` 的可点击范围。
- 在小屏下使用 `overflow-x-auto` + `shrink-0`，避免内容折行挤压。

## 6. 论坛移动端设计

### 6.1 广场首页 Feed

现状中广场已经把热门圈子折到顶部横向滚动，但“我的圈子”和“创建圈子”仍主要存在于桌面侧栏。

移动端目标：

- 顶部保留热门圈子横向卡片区。
- 在移动端增加一块轻量的社区操作区，承接“我的圈子”和“创建圈子”两个侧栏动作。
- 我的圈子在已登录且有加入圈子时，以横向 chips 或卡片列表形式出现在热门圈子区之后。
- 创建圈子按钮在移动端仍保持可见，不依赖桌面侧栏。

### 6.2 圈子主页

圈子主页是本次移动端补齐的重点页面。

移动端目标：

- banner、icon、名称、简介、成员数、帖子数、加入按钮在首屏信息块内完整呈现。
- “发帖”和“管理圈子”两个动作不能只留在桌面侧栏；在移动端需要进入首屏或紧随首屏的信息卡。
- 圈子信息卡在移动端从右侧栏降级为正文中的独立卡片，包含创建时间和创建者。
- 子板块 tabs 继续保留横向滚动，但需要统一与全站通用操作条的样式和触控密度。

### 6.3 探索页

移动端目标：

- 搜索框和排序区按上下结构堆叠，避免在窄屏中形成挤压。
- “创建圈子”按钮在已登录时保持首屏可见，但不挤占搜索区。
- 圈子列表继续单列卡片展示；分页组件需保证在底部有足够点击空间。

### 6.4 帖子详情页

移动端目标：

- 头部作者信息、所属圈子、时间与管理动作之间保持清晰层次。
- 点赞、收藏、举报、置顶等操作区在小屏下保持可点，不出现过窄或换行混乱。
- 评论区与正文、操作区之间留出更明确的间距，避免视觉上挤成一块。

### 6.5 圈子设置页

移动端目标：

- 顶部保留圈子概览和返回按钮。
- 设置 tabs 采用横向滚动 tab rail，并确保当前 tab 在小屏中可辨识。
- 各 tab 面板的顶部间距、卡片内边距和图片上传区在手机上保持可操作。

本次不重构各设置子模块的内部逻辑，只处理入口、导航与容器层面的移动端适配。

## 7. 控制台与后台移动端设计

### 7.1 服主控制台

当前移动端已有服务器下拉选择器，但整个顶部区仍更像桌面信息块压缩。

移动端目标：

- 页头保留“控制台身份”和返回主站入口，但将按钮排列为更稳定的堆叠或换行布局。
- 服务器切换器继续使用下拉，但与“提交新服务器”按钮形成清晰的一组主操作。
- 当前服务器上下文在进入子页后应保持明确，不依赖桌面左侧列表。

桌面侧边栏保持不动，仅优化移动端顶部与选择器区域。

### 7.2 管理后台

当前移动端使用一排 chips，但没有明确当前页态，也缺少横向滚动语义。

移动端目标：

- 将后台导航升级为可横向滚动的移动端导航条。
- 当前页面需要明确高亮。
- 导航条在多入口情况下仍可顺畅滚动，不压缩文字。

### 7.3 圈子设置与后台导航风格统一

圈子设置页的 tabs 和管理后台导航条使用同类的移动端滚动导航模式，提升整体一致性，但不强行共用复杂逻辑。

## 8. 文件边界

为保证并行开发可控，本次实施采用以下边界。

### 8.1 共享骨架域

主要文件：

- `src/app/layout.tsx`

- `src/components/forum/ComposeDialog.tsx`

职责：

- 统一移动端 header、菜单、搜索和 FAB 行为。
- 提供论坛页、后台页可复用的小屏交互模式。

### 8.2 论坛域

主要文件：

- `src/components/forum/FeedPage.tsx`
- `src/components/forum/CirclePage.tsx`
- `src/components/forum/ExplorePage.tsx`
- `src/components/forum/PostDetailPage.tsx`
- `src/components/forum/CircleSettings.tsx`
- 必要时补充相关 page 容器文件

职责：

- 将桌面侧栏信息重排为移动端可见区块。
- 补齐论坛关键页面的小屏操作入口和筛选区。

### 8.3 控制台与后台域

主要文件：

- `src/components/console/Sidebar.tsx`

职责：

- 完善小屏导航、切换与当前态展示。
- 不修改论坛组件和全局 header。

## 9. 风险与约束

### 9.1 共享组件冲突风险

`AuthButtons`、`HeaderSearch`、`ComposeDialog` 都是高复用组件。若在没有边界约束的情况下并行改动，极易产生冲突。因此共享骨架域必须先明确交互结构，再由其余页面域接入。

### 9.2 FAB 与页面操作重复

论坛页内已经存在“发帖”“管理圈子”等按钮。若移动端布局调整不当，用户可能同时看到多个主操作且缺少层级。解决方式是让页头动作与 FAB 互补，而不是竞争。

### 9.3 不扩大业务范围

本次只做 UI 和交互结构补齐，不借机改动权限判断、数据加载方式或 API 设计。

## 10. 验收标准

满足以下条件即可视为本次设计实现达标：

- 移动端 header、搜索、菜单和 FAB 形成一致交互，不再出现过窄搜索入口或菜单语义混乱。
- 广场首页移动端可访问热门圈子、我的圈子和创建圈子。
- 圈子页移动端首屏可完成加入圈子、发帖、进入管理，圈子信息卡不再只存在桌面侧栏。
- 探索页、帖子详情页、圈子设置页在小屏下具备稳定的搜索、操作或 tab 导航体验。
- 控制台与管理后台在移动端具备清晰的导航、当前态和切换入口。
- 桌面端无明显回归，`pnpm lint` 与 `pnpm tsc --noEmit` 通过。

## 11. 实施顺序建议

推荐顺序如下：

1. 先完成共享移动端骨架，锁定全局菜单、搜索、FAB 和滚动操作条模式。
2. 再并行推进论坛域与控制台/后台域。
3. 最后由主控做整合、回归检查和样式统一修正。

这个顺序既满足并行开发效率，也能最大程度降低共享文件冲突。
