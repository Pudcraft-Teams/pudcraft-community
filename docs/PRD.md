# Pudcraft Community — 产品需求文档 (PRD)

> **版本**：v1.0
> **日期**：2026-03-26
> **状态**：Phase 1 已实现，Phase 2-4 规划中

---

## 1. 产品概述

### 1.1 产品定位

Pudcraft Community 是一个面向 Minecraft 玩家的综合社区平台，集服务器发现、社区交流、白名单管理于一体。平台分为两大核心模块：

1. **服务器系统**：帮助玩家发现、评价 Minecraft 服务器，服主管理服务器信息、私域成员和白名单同步。
2. **社区论坛（MoltBook）**：类贴吧 + 类 X（Twitter）混合形态的圈子系统，提供信息流广场（大别野模式）和自由创建的兴趣圈子。

### 1.2 目标用户

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| **普通玩家** | 寻找服务器、参与社区讨论的 MC 玩家 | 发现优质服务器、加入社区交流、收藏和管理感兴趣的内容 |
| **服主** | 运营 Minecraft 服务器的管理者 | 展示服务器、管理成员申请、自动同步白名单、查看统计数据 |
| **圈主** | 创建和管理社区圈子的用户 | 经营兴趣社群、管理成员和内容、建设子板块 |
| **平台管理员** | 维护平台运营的管理者 | 内容审核、用户管理、举报处理、平台运营 |

### 1.3 产品愿景

成为中文 Minecraft 社区的一站式平台——既是服务器导航站，也是玩家交流的社区家园。

## 2. 功能模块

### 2.1 用户系统

#### 2.1.1 注册与登录

- **邮箱注册**：填写邮箱 → 接收 6 位验证码 → 设置密码 → 完成注册
- **邮箱登录**：邮箱 + 密码登录，基于 JWT 的会话管理
- **密码重置**：通过邮箱验证码重置密码

**约束**：
- 密码最少 8 位
- 用户名 2-20 字符
- 验证码 60 秒发送冷却，单 IP 每日上限 10 封
- 验证码连续错误 5 次锁定 15 分钟

#### 2.1.2 用户资料

- **基本信息**：用户名、个人简介（200 字符以内）、头像
- **UID**：系统分配的 9 位唯一数字标识，删号后不回收
- **头像上传**：前端 1:1 裁切 + WebP 压缩（256px），上传至 S3/OSS
- **用户主页**（`/u/:uid`）：展示用户发帖历史、加入的圈子

#### 2.1.3 角色与权限

| 角色 | 权限范围 |
|------|----------|
| **user**（默认） | 浏览、发帖、评论、点赞、收藏、举报 |
| **admin** | 所有 user 权限 + 内容审核、用户封禁、服务器审核、话题管理 |
| **服主**（通过 MOTD 认领） | 服务器编辑、成员管理、统计查看、API Key 管理 |
| **圈主**（OWNER） | 圈子设置、子板块管理、成员角色管理、禁言 |
| **圈子管理员**（ADMIN） | 帖子置顶/隐藏/删除、禁言 |

### 2.2 服务器系统

#### 2.2.1 服务器提交与审核

**提交流程**：
1. 用户填写服务器信息（名称、地址、端口、版本、描述、标签、图标）
2. 系统进行阿里云 AI 内容审核
3. AI 通过 → 直接上线（`status=approved`），进入管理员巡检队列
4. AI 拦截 → 进入待审核队列（`status=pending`），需管理员手动审核

**服务器信息**：

| 字段 | 规则 |
|------|------|
| 名称 | 2-50 字符 |
| 地址（Host） | 域名格式，禁止 localhost/内网 IP（SSRF 防护） |
| 端口 | 1-65535 |
| 描述 | 200 字符以内 |
| 详细内容 | 10000 字符以内，富文本 |
| 标签 | 最多 10 个，每个 ≤ 20 字符 |
| 图标 | 最大 5MB，前端压缩至 512px |
| PSID | 系统分配的唯一标识，删除后不回收 |

#### 2.2.2 服务器认领（MOTD 验证）

1. 服主在平台生成唯一验证 Token
2. 将 Token 写入服务器 MOTD
3. 平台 Worker 后台验证（超时 15 秒）
4. 验证成功 → 服主获得服务器管理权限
5. Token 有效期 30 分钟

#### 2.2.3 服务器状态监控

- **Worker 自动 Ping**：每 5 分钟异步 ping 所有已审核服务器
- **监控数据**：在线状态、玩家人数、最大人数、延迟、MOTD、Favicon
- **历史记录**：`ServerStatus` 表记录每次 ping 结果
- **通知**：服务器从离线恢复在线时通知收藏者（Redis 1 小时冷却防刷）

**状态指示**：
- 在线：`emerald-500`
- 离线：`gray-400`
- 低延迟：`teal-600`
- 中延迟：`yellow-500`
- 高延迟：`red-500`

#### 2.2.4 服务器列表与详情

**列表页**（`/servers`）：
- 分页浏览所有已审核的公开服务器
- 排序：最新、热门、在线人数、名称
- 筛选：标签、服主

**详情页**（`/servers/:id`）：
- 服务器基本信息、实时状态
- 评论区（2 层嵌套评论，最多 1000 字符）
- 收藏按钮
- 整合包下载
- 服主操作面板（编辑、设置入口）

#### 2.2.5 服务器评论

- 支持 2 层嵌套（主评论 + 回复）
- 评论长度 5-1000 字符
- 频率限制：5 条/分钟
- 阿里云 AI 审核（fail-open）
- 作者和管理员可删除

#### 2.2.6 服务器收藏

- 登录用户可收藏/取消收藏服务器
- 收藏列表页面（`/favorites`）
- 收藏数缓存在 Server 表，$transaction 内更新

#### 2.2.7 整合包（Modpack）

- 支持 Modrinth `.mrpack` 格式上传
- 文件大小限制 50MB
- 仅认领后的服主可上传
- 存储至 S3/本地文件系统
- 玩家可下载

### 2.3 私有服务器系统

> 说明：私有服务器子系统已实现，但当前线上默认通过 `NEXT_PUBLIC_ENABLE_PRIVATE_SERVERS` 功能开关关闭；关闭时不展示申请、邀请码和成员管理入口。

#### 2.3.1 可见性模式

| 模式 | 列表展示 | 地址可见 | 到达方式 |
|------|----------|----------|----------|
| **public** | 完全展示 | 所有人 | 直接访问 |
| **unlisted** | 展示名称和简介 | 仅成员 | 申请 / 邀请 |
| **private** | 不展示 | 仅成员 | 仅邀请链接可达 |

#### 2.3.2 加入模式

| 模式 | 说明 |
|------|------|
| **open** | 无需申请，任何人可加入（默认） |
| **apply** | 申请制，需填写表单并等待审核 |
| **invite** | 邀请制，通过邀请码加入 |
| **apply_and_invite** | 同时支持申请和邀请 |

#### 2.3.3 入服申请

**服主端**：
- 自定义申请表字段（text / textarea / select / multiselect），最多 10 个字段
- 查看申请列表（按状态筛选：pending / approved / rejected）
- 审批操作：通过（触发白名单同步）/ 拒绝（可附备注）

**玩家端**：
- 填写服主配置的申请表
- 提交后等待审核
- 收到审核结果通知

#### 2.3.4 邀请码

- 服主生成邀请码，可设置有效期和最大使用次数
- 玩家通过 `/servers/:id/join/:code` 使用邀请码加入
- 服主可撤销邀请码
- 过期或用满自动失效

#### 2.3.5 成员管理

- 查看服务器成员列表（含加入方式、MC 用户名、加入时间）
- 移除成员（触发白名单 remove 同步）
- 成员状态与白名单同步状态实时展示

#### 2.3.6 白名单同步

**架构**：
```
插件 → HTTP → Next.js API
              ↓
           PostgreSQL + Redis PUBLISH
              ↓
           WS Server → WebSocket → 插件
```

**同步流程**：
1. **握手**：插件启动 → `POST /api/servers/:id/sync/handshake`（携带 API Key）→ 返回完整白名单 + WebSocket 地址 → 插件覆盖本地白名单
2. **实时推送**：成员变更 → Redis Pub/Sub → WebSocket Server → 推送 `whitelist_add` / `whitelist_remove` 事件
3. **确认**：插件执行白名单操作 → `POST /api/sync/:syncId/ack` → 更新同步状态
4. **容错**：推送无 ACK → 指数退避重试 3 次（5s, 15s, 45s）→ 超时标记 failed → 插件重连时 handshake 自动补齐

**同步状态**：`pending` → `pushed` → `acked` / `failed`

#### 2.3.7 API Key 管理

- 服主在控制台生成 API Key（绑定到具体服务器）
- API Key 哈希存储（bcryptjs），完整密钥仅在生成时展示一次
- 可重新生成（旧密钥立即失效）
- 用于 Minecraft 插件认证

### 2.5 社区论坛（MoltBook）

#### 2.5.1 信息流广场（大别野）

路由：`/`（首页）

- 全站最新帖子流，包括圈子内帖子和广场直发帖子
- 游标分页 `(createdAt, id)`，每页 20 条
- 右侧边栏（桌面端）：热门圈子推荐 + 我加入的圈子
- 支持不属于任何圈子的帖子直发广场（`circleId = null`）
- 大别野帖子仅全站管理员可管理

#### 2.5.2 圈子

**创建圈子**（`/circles/create`）：
- 填写名称、slug（URL 标识，唯一）、简介、图标、横幅
- 创建者自动成为 OWNER
- 加入圈子无需审核，退出自由
- 不加入可浏览，不能发帖和评论

**圈子主页**（`/c/:slug`）：
- 顶部：横幅 + 名称 + 简介 + 成员数 + 加入/已加入按钮
- 子板块 Tab 筛选栏
- 帖子 feed（游标分页）
- 右侧边栏：圈子信息、管理入口（OWNER/ADMIN 可见）

**圈子发现页**（`/explore`）：
- 热门圈子列表，按成员数排序
- 圈子卡片：图标 + 名称 + 简介 + 成员数/帖子数 + 加入按钮
- 创建圈子入口

**圈子管理**（`/c/:slug/settings`）：
- 圈子信息编辑（名称、简介、图标、横幅）
- 子板块管理（CRUD、排序）
- 成员管理（查看成员列表、设置/撤销 ADMIN 角色、移除成员）
- 禁言管理（禁言/解禁用户，支持临时禁言设置到期时间）
- 关联服务器

#### 2.5.3 子板块（Section）

- 圈主/管理员在圈子内创建子板块，用于分类帖子
- 每个子板块有名称、描述、排序权重
- 帖子可选择发到指定子板块，也可不选
- 圈子主页支持按子板块 Tab 筛选

#### 2.5.4 帖子

**发帖**（`/new` 或 `/c/:slug/new`）：
- 选择发到广场或指定圈子（圈子内发帖需先加入）
- 填写标题 + 富文本内容（TipTap 编辑器，支持图片、链接、代码、Markdown）
- 自动提取 `#话题` 标签（最多 5 个）
- 阿里云 AI 内容审核（fail-open）

**帖子详情**（`/c/:slug/post/:postId` 或 `/post/:postId`）：
- 顶部：作者头像 + 用户名 + 发布时间 + 所属圈子
- 正文：Markdown 渲染（代码高亮、GFM 支持）
- 操作栏：点赞 / 收藏 / 分享
- 评论区
- OWNER/ADMIN 操作：置顶 / 隐藏 / 删除

**帖子卡片**（Feed 中）：
- 作者头像 + 名称 + 相对时间
- 所属圈子标签（大别野显示"广场"）
- 标题 + 内容预览（纯文本截取前 200 字符）
- 底部：点赞数 / 评论数 / 浏览数 / 收藏按钮

**帖子状态**：`PUBLISHED` / `HIDDEN` / `DELETED`

#### 2.5.5 评论系统

- 数据库存储：无限嵌套自引用（parentCommentId）
- 前端展示：2 级嵌套 + 行内回复框，超过 2 级平铺显示 "回复 @某人"
- 评论长度 1-1000 字符
- 阿里云 AI 审核（fail-open）
- 游标分页，每页 30 条
- 作者可删除自己的评论，圈子管理员/全站管理员可删除任意评论

#### 2.5.6 点赞

- **帖子点赞**（PostLike）：toggle 操作，`likeCount` 缓存字段在 $transaction 内更新
- **评论点赞**（CommentLike）：toggle 操作，同上
- 当前用户点赞状态通过 ID 列表批量查询

#### 2.5.7 收藏

- **帖子收藏**（Bookmark）：toggle 操作
- 收藏列表页面（`/user/bookmarks`）
- 唯一约束 `(userId, postId)` 防重复

#### 2.5.8 话题系统

- 用户在帖子正文中使用 `#话题` 标记
- 发帖时自动提取话题标签，每帖最多 5 个
- 话题名称大小写不敏感，存储小写，显示保留首次创建时的原始形式
- 话题可点击跳转至搜索页筛选相关帖子
- 话题表包含 `postCount` 缓存字段
- 支持别名（aliases），搜索时一并匹配

**管理员话题管理**（`/admin/tags`）：
- 列表、重命名（旧名自动加入别名）、设置别名、合并话题、删除

#### 2.5.9 搜索

路由：`/search?q=xxx`

| 前缀 | 行为 |
|------|------|
| `#话题` | 按话题筛选帖子，匹配 Tag.name + Tag.aliases |
| `@用户名` | 搜索用户 |
| 纯文本 | 搜索帖子标题和内容（PostgreSQL ILIKE） |

- 游标分页，每页 20 条
- 话题搜索时顶部显示话题卡片（名称 + 帖子数）

#### 2.5.10 圈内禁言

- OWNER / ADMIN 可禁言圈内用户
- 支持永久禁言或设置到期时间
- 被禁言用户无法在该圈子发帖和评论
- `syncToServers` 字段预留，Phase 1 不实现跨服务器同步

### 2.7 举报与审核系统

#### 2.7.1 举报

**举报对象**：服务器、服务器评论、论坛帖子、论坛评论、用户

**举报分类**：
- 虚假信息（misinformation）
- 色情低俗（pornography）
- 骚扰攻击（harassment）
- 广告欺诈（fraud）
- 其他（other）

**举报入口**：
- 服务器详情页操作栏
- 评论更多菜单
- 帖子操作菜单
- 用户主页

**防滥用信誉机制**：
- 查询过去 30 天被驳回（dismissed）的举报数量
- 0-2 次驳回 → 每日上限 10 次
- 3-5 次驳回 → 每日上限 3 次
- 6+ 次驳回 → 每日上限 1 次

#### 2.7.2 AI 内容审核

- **审核引擎**：阿里云绿网 API
- **审核场景**：服务器名称/描述、评论、帖子内容、用户名/简介、整合包文件
- **审核分类**：色情、暴力、恐怖、广告、辱骂、垃圾信息
- **策略**：fail-open（API 错误时放行，不阻塞用户操作）
- **审计追踪**：ModerationLog 记录所有审核结果，管理员可复查

#### 2.7.3 管理员审核后台

**服务器审核**（`/admin/servers`）：

| Tab | 内容 |
|-----|------|
| 待审核 | AI 拦截的服务器（status=pending） |
| 待巡检 | AI 通过但未人工巡检（reviewStatus=unreviewed） |
| 被举报 | 有未处理举报的服务器 |
| 已巡检 | 已完成人工巡检 |

**举报管理**（`/admin/reports`）：

| Tab | 内容 |
|-----|------|
| 待处理 | status=pending，按 targetType 筛选 |
| 已处理 | status=resolved 或 dismissed |

**管理员操作**：
- 巡检：标记已巡检 / 下架（填原因）
- 举报处理：驳回举报 / 警告发布者 / 下架内容 / 封禁用户（可多选）
- 用户管理：封禁/解封用户（`/admin/users`）
- 审核日志：查看 AI 审核记录（`/admin/moderation`）

## 3. 非功能需求

### 3.1 性能

| 指标 | 要求 |
|------|------|
| API 响应时间 | < 200ms |
| 数据库查询告警 | > 100ms |
| MC Ping 超时 | 5 秒 |
| Worker 单任务超时 | 10 秒 |
| MOTD 验证超时 | 15 秒 |
| 图片上传 | 前端压缩后上传（头像 256px，图标 512px，编辑器图片 1920px） |

### 3.2 安全

- **输入校验**：所有 API 输入经 Zod 校验，地址字段 SSRF 防护
- **密钥管理**：环境变量管理，不硬编码
- **权限校验**：所有写操作服务端校验，不依赖前端按钮隐藏
- **地址保护**：私有/未列出服务器地址对非成员隐藏
- **API Key**：哈希存储（bcryptjs），仅展示一次
- **外链安全**：用户链接强制 `rel="noopener noreferrer" target="_blank"`
- **XSS 防护**：禁止 `dangerouslySetInnerHTML` 渲染用户输入
- **频率限制**：注册/登录/评论/收藏/举报均有频率限制

### 3.3 可靠性

- 缓存字段更新与关联操作在同一 `$transaction` 中，保证一致性
- 副作用失败只记日志，不阻塞主操作
- AI 审核 fail-open 策略，API 故障不影响用户操作
- 白名单同步失败后指数退避重试 + 插件重连自动补齐
- Worker 任务幂等，使用 `jobId` 去重

### 3.4 可用性

- 移动端优先响应式设计，断点：sm(640) / md(768) / lg(1024)
- Material 3 浅色主题，品牌色 `#e2f4f7`，强调色 teal 系
- 统一 Toast / EmptyState / LoadingSpinner 组件
- 使用 Next.js `<Image>` 图片优化

## 9. 接口规范

详细 API 文档见 [`docs/API.md`](./API.md)。

**通用规范**：
- 认证：JWT Bearer Token（通过 NextAuth session）
- 输入校验：Zod schema，校验失败返回 400 + 字段错误
- 错误格式：`{ error: string, details?: unknown }`
- 状态码：401 未登录 / 403 无权限 / 404 未找到 / 400 校验失败 / 409 已存在 / 429 频率限制
- 分页：Feed 使用游标分页 `(createdAt, id)`，管理列表使用偏移分页
